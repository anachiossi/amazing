3. Coordinates: (x, y)

Internally everything is (x, y), that is (column, row): the same order
the config file uses. The grid is indexed grid[x][y].
Nothing is ever converted, anywhere.

  EXIT=19,14    in the config file
  (19, 14)      in the code
  19,14         in the output file

19 is ALWAYS the column, 14 is ALWAYS the row. It is the bottom-right
cell: column of index 19 (the twentieth) and row of index 14 (the
fifteenth).

grid is a list of COLUMNS, not of rows: grid[x] is column x, HEIGHT
cells tall. That way the order of the two indices is always the same
as the order of the coordinates.

The only place that thinks in rows is writing the output file, which
the subject wants one line per row of the grid:

  for y in range(height):
      row = "".join(digit(grid[x][y]) for x in range(width))

That is not a conversion: it is only the order in which the grid is
traversed.

Wall bits (1 = closed):

  bit 0 = N = (x, y - 1)
  bit 1 = E = (x + 1, y)
  bit 2 = S = (x, y + 1)
  bit 3 = W = (x - 1, y)

y grows DOWNWARDS, as on screen: that is why N is y - 1.
